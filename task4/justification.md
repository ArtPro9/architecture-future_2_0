# Почему конфигурация Terraform именно такая

| Параметр                          | Что выбрали                                                                           | Зачем декларативный подход                                         | Польза от Infrastructure as Code                                          | Примечание                                                                  |
|-----------------------------------|---------------------------------------------------------------------------------------|--------------------------------------------------------------------|---------------------------------------------------------------------------|-----------------------------------------------------------------------------|
| Сеть (VPC) и подсеть              | Сеть corp-network и подсеть domain-subnet (например, 10.10.0.0/24) для одного домена  | Описываем что нужно (сеть и подсеть) без ручных шагов              | Код под версионированием, легко разворачивать для новых доменов           | Изоляция домена (финтех, ИИ, медицина) — меньше риска пересечений           |
| Виртуальная машина: 4 ядра, 16 ГБ | VM с 4 ядрами и 16 ГБ памяти — ориентир для аналитической нагрузки и витрин данных    | Декларативно задаем конфигурацию, Terraform сам подберет операции  | Можно повторно развернуть с теми же ресурсами                             | Подходит для бизнес-аналитики, отчетов и портала самообслуживания           |
| Диск: network-ssd, 1 ТБ           | Диск типа network-ssd, объем 1024 ГБ                                                  | Большой объем настроен через код — удобно масштабировать           | Инфраструктура как код позволяет сменить размер или тип без ручной работы | Для старта 1 ТБ, дальше масштабируемся                                      |
| NAT-интерфейс                     | NAT включен (nat = true), чтобы VM имела выход в интернет для обновлений и интеграций | Конфигурация описана один раз — нет ручных настроек                | Повторяемость: все домены получат одинаковую сетевую конфигурацию         | Важно для доступа, при этом входящие порты можно ограничить                 |
| Флаг enable_real = false          | Переменная-флаг переключает режим: песочница или реальное развертывание               | Код легко адаптируется: единственный флаг — и мы в тестовом режиме | IaC делает среду воспроизводимой и безопасной для тестов                  | По умолчанию песочница — минимизирует риск затрат и случайных изменений     |
| Бэкенд local                      | Локальное хранение состояния (terraform.tfstate) для тестового режима                 | Можно сменить backend без переписывания конфигурации               | Версия инфраструктуры под контролем, удобно для разработки                | При переходе к реальной среде заменим на удаленный backend (S3-совместимый) |

## Как IaC помогает воспроизводимости и масштабированию

- Конфигурации хранятся в системе контроля версий (Git и др.). Можно откатиться к предыдущей версии, аудитировать
  изменения.
- Среды можно легко дублировать: тестовая, пред-прод, прод.
- Масштабирование: для нового домена достаточно повторно использовать тот же шаблон инфраструктуры, изменив только
  параметры — код остается неизменным.
